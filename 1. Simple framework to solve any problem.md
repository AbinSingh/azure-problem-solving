Use this simple framework for almost any task in a company — whether it's agentic development, building an API, 
fixing a bug, or delivering a project.

##########################
# 1. The 5-step approach #
##########################

# 1. Define the goal

What exactly needs to be achieved? What does success look like?

Output: One clear sentence defining the expected result.

# 2. Understand only what you need

Identify the inputs, outputs, constraints, and the most important unknowns. Don't investigate every possibility.

Output: Enough understanding to start, not perfect understanding.

# 3. Find the smallest working solution

Break the task into small steps. Choose the simplest approach that proves the core idea.

Output: A basic plan you can execute.

# 4. Build, test, and get feedback

Complete one small piece. Run it, inspect the result, and identify what is actually missing.

Output: Evidence of progress, not just more planning.

# 5. Handle edge cases and improve

Once the basic solution works, address failures, security, performance, reliability, and maintainability according to 
the project's needs.

Output: A robust solution ready for its intended use.

####################################
# 2. Example: Building an AI agent #
####################################

Instead of immediately thinking about every possible tool failure, infinite loops, memory, retries, permissions, and 
scaling:

- Goal: The agent should answer questions using company documents.
- Understand: It needs document retrieval, an LLM, and a response.
- Smallest solution: Retrieve one relevant document and generate an answer from it.
- Test: Try five realistic questions and inspect the results.
- Improve: Add citations, handle missing information, prevent unauthorized access, and introduce retries or other 
- reliability features where needed.

You solve the real problem first, then make the solution robust.

####################################################
# 3. The rule that will help you stop overthinking #
####################################################

Before starting, ask yourself:

- What is the simplest thing I can build or do that demonstrates progress?
- What do I genuinely need to know before taking the first step?
- Can I postpone this decision until I have more information?

#########################################################################################################
# 4. If an unknown doesn't block your next step and isn't a critical safety or business risk, defer it. #
#########################################################################################################

Remember:

- Think enough to start.
- Build enough to learn.
- Learn enough to improve.

You don't need to foresee every edge case. You need a process that helps you discover and handle them systematically.
